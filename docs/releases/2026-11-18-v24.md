### Guest HTML byte comparison and rollback decision

The first automated comparison used the version 23 source file as its baseline, rather than a captured predeployment HTTP response. It found 1,978 served bytes versus 864 source bytes because Cloudflare appended a challenge-platform script before closing the body. The underlying guest-page app source is unchanged, but a literal byte-for-byte comparison against the previously published response could not be established. The release was conservatively rolled back under the handoff's requirement that the guest-page check pass.

After rollback, version 23 also served 1,978 bytes with the same kind of Cloudflare insertion and the expected app prefix. Thus the observation is a hosting-layer transformation, **not evidence of a tooltip-release regression**. The source file is byte-identical across both commits; the literal wire-response equality requirement remains unresolved. A future release handoff should specify how to compare app HTML when the hosting layer adds dynamic code; no stripping or exception was silently treated as a passing literal check here.
